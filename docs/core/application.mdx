# Application Structure

<PageStatus value="beta">
The library layout (`app.New`, `app.Main`) shipped in v1.2. Before 1.2, projects were full clones of the framework repository.
</PageStatus>

Mithril is a **library** you import. A project created with `mithril new` contains only your code; framework fixes arrive with `go get -u github.com/mithril-framework/mithril`.

## Project layout

```
shop/
├── main.go           # builds the app and runs commands
├── resources.go      # declarative resources (CRUD + OpenAPI + permissions + admin)
├── routes.go         # custom typed endpoints
├── models/           # structs behind resources
├── migrations/       # goose SQL files, embedded into the binary
├── main_test.go      # smoke test (no database needed)
├── AGENTS.md         # conventions for AI coding agents
├── .mcp.json         # MCP server config (go run . mcp)
├── docker-compose.yml, Dockerfile, Makefile, env.example, .env
└── go.mod            # requires github.com/mithril-framework/mithril
```

## main.go

```go
package main

import (
    "embed"

    "github.com/mithril-framework/mithril/app"
)

//go:embed migrations
var migrations embed.FS

func main() {
    a := app.Must(app.New(app.WithMigrations(migrations, "migrations")))
    a.Register(resources()...)
    routes(a)
    app.Main(a)
}
```

`app.New` reads [configuration](/docs/core/configuration), sets up the [middleware stack](/docs/core/middleware), and mounts the built-in routes. `app.Main` serves HTTP when run without arguments and otherwise runs a [management command](/docs/cli/overview).

### Options

| Option | Purpose |
| --- | --- |
| `app.WithMigrations(fsys, dir)` | App migrations (usually an `embed.FS`) |
| `app.WithViews(fsys, dir, ".jet")` | Jet templates, embedded |
| `app.WithStatic("/static", fsys, dir)` | Static files, embedded |
| `app.WithConfig(cfg)` | Use a `config.Config` instead of the environment (tests) |
| `app.WithEnvFile(path)` | `.env` file to merge (default `.env`; `""` disables) |
| `app.WithVersion("1.4.0")` | Version shown in the OpenAPI document |
| `app.WithMiddleware(handlers...)` | Global middleware before every route (see [Middleware](/docs/core/middleware)) |
| `app.WithoutDatabase()` | Never connect (tests, tooling) |

## What the app gives you

| Field / method | Description |
| --- | --- |
| `a.Fiber` | The underlying `*fiber.App` for anything custom |
| `a.API` | `/api` typed router: access token required, 503 while the DB is down |
| `a.Public` | Root typed router without auth |
| `a.Doc` | The OpenAPI document |
| `a.Register(resources...)` | Add [resources](/docs/core/resources) |
| `a.RequirePermission("x.y")`, `a.RequireSuperuser()` | Middleware for custom routes |
| `a.DB()`, `a.ACL()`, `a.Users()` | Pool, ACL service and user repository (nil until connected) |
| `a.Routes()`, `a.Resources()`, `a.Migrations()` | Introspection, also used by the MCP server |

## Built-in routes

| Route | Notes |
| --- | --- |
| `GET /`, `/health`, `/livez`, `/readyz` | `/health` and `/readyz` check the database |
| `/auth/*` | [JWT authentication](/docs/authentication/jwt) |
| `/api/users/*` | User management with self-service rules |
| `/openapi.json`, `/docs` | [OpenAPI and Swagger UI](/docs/api/swagger) |
| `/admin`, `/admin/api/*` | Admin panel (`ENABLE_ADMIN_PANEL`) |
| `/monitor` | Superusers only (`ENABLE_MONITOR`) |

## Database lifecycle

`serve` connects to PostgreSQL at startup. In development, if the database is down, the app still starts, answers **503** on database routes, and reconnects in the background every 5 seconds. In production (or with `APP_ENV` unset) a missing database stops startup. On connect, Mithril creates permission codenames for every registered resource and warns about pending migrations.

## Framework packages

| Package | Purpose |
| --- | --- |
| `app` | Application builder and commands |
| `config` | Typed configuration |
| `resource` | Declarative resources |
| `api` | Typed handlers and validation |
| `openapi` | OpenAPI document and schema reflection |
| `auth`, `acl`, `users`, `admin` | Authentication, RBAC, user management, admin panel |
| `migrate`, `db` | Migrations and the pgx pool |
| `mcpserver`, `scaffold` | AI tooling and generators |
| `pkg/utils` | [Utilities](/docs/core/utilities) |
