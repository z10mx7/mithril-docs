# CLI Overview

<PageStatus value="beta">
The command set was reorganized in v1.2: project commands now run inside your app (`go run . <command>`) instead of through `make`.
</PageStatus>

There are two layers:

1. **`mithril`** (global CLI): creates projects, runs generators, and forwards everything else to your app.
2. **Your app's binary**: every Mithril app understands management commands, much like Django's `manage.py`. `mithril migrate up` inside a project is exactly `go run . migrate up`, and in production you run `./app migrate up`.

## Global commands

| Command | Description |
| --- | --- |
| `mithril new [-module path] [-local path] <name>` | Create a project from the built-in template. `-local` points `go.mod` at a local framework checkout (for contributors). |
| `mithril make:resource <Model> [fields...] [--owner] [--name table] [--dry-run]` | Generate a [resource](/docs/core/resources): model, migration and registration. Fields are `name:type` or `name:type:required`. |
| `mithril --version`, `mithril help` | Version and usage |
| `mithril init` | Symlink the CLI into `/usr/local/bin` |

## App commands

| Command | Description |
| --- | --- |
| `serve` (default) | Start the HTTP server |
| `migrate up` | Apply core and app migrations, then create resource permissions |
| `migrate down` | Roll back the latest **app** migration (core migrations are never rolled back) |
| `migrate status` | Applied and pending migrations |
| `routes [--json]` | Every route |
| `openapi [-o file]` | The OpenAPI 3.1 document |
| `resources` | Registered resources as JSON (fields, permissions, paths) |
| `createsuperuser [--email E --password P] [--first-name F --last-name L]` | Create a superuser (interactive without flags; also reads `CREATESUPERUSER_EMAIL` / `CREATESUPERUSER_PASSWORD`) |
| `acl …` | Roles, permissions and superusers (see below) |
| `dbms [addr]` | Embedded PostgreSQL web UI (default `127.0.0.1:5050`) |
| `mcp` | [MCP server](/docs/ai/agents) on stdio for AI coding agents |
| `version`, `help` | |

```bash
mithril new -module github.com/acme/shop shop
cd shop
docker compose up -d postgres
mithril migrate up
mithril createsuperuser --email admin@acme.test --password 'change-me-now'
mithril make:resource Product name:string:required price:float --owner
mithril migrate up
mithril serve
```

## ACL

```bash
mithril acl superuser set|unset EMAIL
mithril acl role create NAME [description]
mithril acl role delete NAME
mithril acl permission create CODENAME [description]
mithril acl assign role USER_EMAIL ROLE_NAME
mithril acl assign permission role ROLE_NAME CODENAME
mithril acl assign permission user USER_EMAIL CODENAME
mithril acl revoke role|permission ...
mithril acl list permissions|roles
```

## Framework repository (contributors)

The framework repo is itself a Mithril app (the reference app with the `blogs` example). Its `Makefile` wraps the same commands (`make run`, `make migrate-up`, `make routes`, `make openapi`, `make createsuperuser`) and adds framework-only tooling: `make backup` / `make restore`, `make seed`, Docker dev services (`make dc-up-postgres`, …) and `make test`.

Projects created before v1.2 (full clones of the framework) keep working: `mithril <target>` still delegates to `make` when the project doesn't import Mithril as a library.

## Removed in 1.2

| Old | Replacement |
| --- | --- |
| `mithril crud MODEL=X` | `mithril make:resource X ...` |
| `mithril swagger` (OpenAI) | `/openapi.json`, `mithril openapi` (generated from types, offline) |
| `mithril migrate-reset` | `mithril migrate down` / recreate the database |
| `LIST_ROUTES=1 go run .` | `mithril routes` |
