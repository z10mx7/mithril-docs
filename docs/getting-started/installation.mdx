# Installation

<PageStatus value="shipped" />

## Prerequisites

- **Go 1.26+**: [download Go](https://go.dev/dl/)
- **PostgreSQL 14+**: Docker is the easiest way (`docker compose up -d postgres` in a new project)
- **Git** (optional; `mithril new` initializes a repository when it's available)

## Install the CLI

```bash
go install github.com/mithril-framework/mithril/cmd/mithril@latest
mithril --version   # mithril 1.3.0 (github.com/mithril-framework/mithril)
```

Make sure `$(go env GOPATH)/bin` is on your `PATH`:

```bash
export PATH="$(go env GOPATH)/bin:$PATH"   # add to ~/.zshrc or ~/.bashrc
```

The install script does the same and checks for older CLIs that shadow it:

```bash
curl -fsSL https://raw.githubusercontent.com/mithril-framework/mithril/main/install.sh | sh
```

### Prebuilt binaries

Every merge to `main` publishes a [GitHub release](https://github.com/mithril-framework/mithril/releases) with the CLI for Linux, macOS and Windows (amd64 and arm64) and a `checksums.txt`. For example, on Linux arm64:

```bash
V=1.3.0   # pick a version from the releases page
curl -fsSLO "https://github.com/mithril-framework/mithril/releases/download/v$V/mithril_${V}_linux_arm64.tar.gz"
curl -fsSLO "https://github.com/mithril-framework/mithril/releases/download/v$V/checksums.txt"
sha256sum --ignore-missing -c checksums.txt     # macOS: shasum -a 256 --ignore-missing -c checksums.txt
tar -xzf "mithril_${V}_linux_arm64.tar.gz"
sudo mv "mithril_${V}_linux_arm64/mithril" /usr/local/bin/
```

You still need Go to build the projects the CLI creates.

## Create a project

```bash
mithril new -module github.com/you/shop shop
cd shop
docker compose up -d postgres
mithril migrate up
mithril serve
```

`mithril new` writes a small project from the template built into the CLI; it no longer clones the framework repository. The project's `go.mod` requires `github.com/mithril-framework/mithril`, so framework updates are a `go get -u` away. Without `-module`, the module path defaults to `github.com/<your GitHub user>/<name>` when `gh` or `git config github.user` knows your username, else to the folder name.

See the [Quick Start](/docs/getting-started/quick-start) for the full first-run walkthrough.

## Working on the framework itself

```bash
git clone https://github.com/mithril-framework/mithril.git
cd mithril
cp env.example .env
make dc-up-postgres
make migrate-up
make run
```

The repository root is a reference app (with a `blogs` example resource) built on the library. To try your framework changes in a separate project, point it at your checkout:

```bash
mithril new -local ../mithril demo     # adds a replace directive to go.mod
```

## Troubleshooting

**`mithril: command not found`**: add `$(go env GOPATH)/bin` to `PATH` (see above).

**`go mod tidy failed` during `mithril new`**: the requested framework version isn't reachable yet (for example, offline). Run `go mod tidy` inside the project later, or use `-local` with a checkout.

**`JWT_SECRET is required`**: `APP_ENV` is unset or set to production, which require a strong secret. Set `APP_ENV=development` for local work, or generate one with `openssl rand -base64 32`.

**`database unavailable` / 503 on `/api`**: in development the app starts without a database and keeps retrying. Check `DATABASE_URL` / `DB_*` and `docker compose ps`.

**Projects created before 1.2**: they keep working; `mithril <target>` still runs their `make` targets. To migrate one to the library layout, create a new project and move your models and migrations over (see [Migrations](/docs/database/migrations#upgrading-a-pre-12-project)).
