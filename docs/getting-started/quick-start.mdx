# Quick Start

<PageStatus value="beta">
This is the v1.2 workflow (Mithril as a library). Requires Go 1.26+ and Docker (or any PostgreSQL 14+).
</PageStatus>

## 1. Install the CLI

```bash
go install github.com/mithril-framework/mithril/cmd/mithril@latest
```

## 2. Create a project

```bash
mithril new -module github.com/you/shop shop
cd shop
```

You get a small project that **imports** Mithril: `main.go`, `resources.go`, `routes.go`, `models/`, `migrations/`, a `.env` with a freshly generated `JWT_SECRET`, a Dockerfile, `AGENTS.md` and `.mcp.json`. See [Application Structure](/docs/core/application).

## 3. Start PostgreSQL and migrate

```bash
docker compose up -d postgres
mithril migrate up
mithril createsuperuser --email admin@shop.test --password 'change-me-now'
```

`migrate up` creates Mithril's core tables (users, roles, permissions) and applies your own migrations.

## 4. Run it

```bash
mithril serve
```

| URL | What |
| --- | --- |
| http://localhost:4000/hello?name=Ada | The example typed endpoint in `routes.go` |
| http://localhost:4000/docs | Swagger UI, generated from your Go types |
| http://localhost:4000/admin | Admin panel (sign in with the superuser) |
| http://localhost:4000/health | Health check |

## 5. Add a resource

```bash
mithril make:resource Product name:string:required description:text price:float in_stock:bool --owner
mithril migrate up
mithril serve
```

That one command wrote `models/product.go`, a migration, and a line in `resources.go`. You now have:

- `GET/POST /api/products`, `GET/PATCH/PUT/DELETE /api/products/:id`, validated and paginated
- `products.view/add/change/change_any/delete/delete_any` permissions (owners manage their own rows)
- a **Products** page in the admin panel
- the operations in `/openapi.json` and `/docs`

## 6. Call the API

```bash
TOKEN=$(curl -s localhost:4000/auth/login -H 'Content-Type: application/json' \
  -d '{"email":"admin@shop.test","password":"change-me-now"}' | jq -r .data.tokens.access_token)

curl -s localhost:4000/api/products -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"name":"Mug","price":9.5,"in_stock":true}'

curl -s localhost:4000/api/products -H "Authorization: Bearer $TOKEN"
# {"items":[{"id":"…","name":"Mug","price":9.5,…}],"total":1,"limit":20,"offset":0}
```

Give regular users access through roles:

```bash
mithril acl role create seller
mithril acl assign permission role seller products.add
mithril acl assign permission role seller products.change   # own products only
mithril acl assign role ada@shop.test seller
```

## 7. Ship it

```bash
docker build -t shop .
docker run --rm --env-file .env shop migrate up
docker run --rm -p 4000:4000 --env-file .env shop
```

The binary embeds its migrations: see [Docker & Single Binary](/docs/deployment/docker).
