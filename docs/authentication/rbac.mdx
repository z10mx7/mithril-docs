# RBAC

<PageStatus value="shipped" />

Mithril provides Django-inspired role-based access control (RBAC) in `internal/acl/`.

## Concepts

- **Permissions** — codenames like `users.view`, `blogs.add`
- **Roles** — named groups of permissions (e.g. `editor`)
- **User assignments** — users get roles and/or direct permissions
- **Superuser** — bypasses all permission checks

## Middleware

[Resources](/docs/core/resources) check their own `<name>.*` permissions automatically. For custom routes:

```go
api.Get(a.API, "/reports", listReports, api.Op{}, a.RequirePermission("reports.view"))
a.Fiber.Post("/api/maintenance", a.RequireSuperuser(), runMaintenance)
```

The `acl` package also has `RequireRole`, `RequireAnyPermission`, `RequireAdminAccess` and `RequireSuperuserDB` for use with an `*acl.Service`.

Privilege changes are always checked against the **database**, not the token: only a superuser can grant or remove superuser status, edit or delete a superuser account, or change roles and permissions. Nobody can change their own superuser or active flag.

## Ownership

Resources with an owner field (`mithril:"owner"`) let owners manage their own rows with `<name>.change` / `<name>.delete`, while `<name>.change_any` / `<name>.delete_any` cover everyone's rows and `<name>.view` lets users read all rows. See [Resources → Permissions](/docs/core/resources#permissions).

## ACL CLI

```bash
mithril acl role create editor "Can edit content"
mithril acl permission create reports.view
mithril acl assign permission role editor blogs.change_any
mithril acl assign role ada@example.com editor
mithril acl assign permission user ada@example.com reports.view
mithril acl revoke role ada@example.com editor
mithril acl superuser set admin@example.com
mithril acl list roles
```

(`mithril acl` runs `go run . acl` in your project.)

## Admin Panel Access

`/admin` requires the `admin.access` permission or superuser status. Enable it with `ENABLE_ADMIN_PANEL=true` (on by default in new projects' `.env`).

`admin.access` alone lets staff browse users, roles and permissions. Resource pages also require that resource's permissions (`blogs.view`, `blogs.change_any`, …), and every ACL change requires a superuser.

## Database Tables

The ACL tables are created by Mithril's embedded core migration (`go run . migrate up`). Models are in `database/models`.
